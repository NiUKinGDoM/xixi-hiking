### v1.2.4.5 —— 弹窗互斥 + 云同步两处修复 + 里程碑逐个庆祝 + 快捷方式改版

- 【修复】**云端「最多保留 2 份」的清理看不见老备份 ⇒ 备份一直堆积**（用户反馈「上传了一堆，不是说最多两个吗」）
  - 根因：`SYNC_FILE_EXT` 于 2026-08-25 从 `.html` 改为 `.zip`，而 `listSyncFilesFromCloud()` 只认当前后缀 ⇒ **8-25 之前上传的 `.html` 备份永远列不出来**，清理逻辑不知道它们存在 ⇒ 永远删不掉。
  - 修法：列表同时接受 `.zip` 与 `.html`（老备份仍可下载导入）。mock 实测（造 3 个老 html + 3 个新 zip）：改前只识别 3 个 → 改后 **6 个全识别**，删除 4 个、保留最新 2 个 zip ✓
- 【修复】**「点上传显示目录检查失败」**
  - 根因：`982` 行注释写「逐级创建目录（405/409 视为 OK）」，但实现是 GET 探测且只认 `200/301/302/403` ⇒ **WebDAV 上 GET 目录常返回 405**，直接误判失败。
  - 修法：① `405` 加入「目录已存在」白名单；② 真 404 时**自动 MKCOL 创建**（不再要用户去网盘手建）；③ 401/403（认证）、429（限流）、网络异常分别给可读提示。mock 实测：GET 405 → 通过；GET 404 → 自动创建后通过 ✓
- 【新增】**里程碑庆祝改为「解锁几个弹几个」**（用户要求）
  - 原行为：单个里程碑弹庆祝卡；**多个同时解锁会合并成一张汇总卡**。
  - 现行为：全部入队 → 弹第一个 → 点「收下」后 280ms 弹下一个，**每张都撒 400 粒彩带**，卡上显示「还有 N 个里程碑待解锁」。
  - 实测（一次解锁 3 个）：3 次弹窗、每张 400 粒彩带、剩余提示 2/1/—、第 4 次不再弹 ✓
  - `_test_p0p3.js` 原有 7 条断言写的是旧「汇总卡」行为 → 按新行为重写并**新增强断言**（队列长度 / 彩带粒数 / 第 2 张接续）⇒ 299 → **303**。
- 【新增】**记下第一条记录后的一次性正反馈弹窗**
  - 内容：「第一笔已记下 / 概览页已经亮起第一格…」+ 两个按钮（知道了 / 去概览看看）；`localStorage` 记标记，只弹一次。
  - **时序处理**：排在里程碑卡之后（若里程碑正在弹，等它关掉再弹，避免两窗叠）；这条正好也被本版新增的「弹窗互斥」兜住。
  - 按钮用 `.glass-btn`（**不用 `.check-go-btn`** —— 那是浅红玻璃的危险语义，第一版错用已纠正）。
- 【新增】**桌面快捷方式**：图标换成专用矢量图（`res/drawable/ic_shortcut_hike.xml`，人形+登山杖+斜坡+山），标签改为「新建计划 / 新建一次徒步计划」，点击行为由「添加记录」改为「添加计划」（`app-init.js` 新增 `addplan` 分支：切计划页 + 轮询调 `addNewPlannedTrip`，**先检测已弹出再调**，防重复新建空计划）。原 `quickadd` 分支保留，改 `shortcuts.xml` 的 value 即可切回。
  - 图标选型：渲染对比 5 版，「三角框+人」版像「注意行人」交通标志被否；最终版在 **32px / 48px 实机尺寸**下仍能认出「人往山上走」。
- 【修复】**通知权限已开启、App 内引导行仍一直显示**
  - 根因：`refreshNotifyPermRow()` 只在 **①启动首帧 ②切到设置页** 检测 ⇒ 用户点引导行跳系统设置、开完权限返回时这两处都不会再跑。
  - 修法双路：**JS** 首次调用时注册 `visibilitychange` / `pageshow` / `resume`（+ Capacitor App resume）一次性监听；**原生** `MainActivity` 新增 `onResume()`，`evaluateJavascript` 主动调 `refreshNotifyPermRow()`（部分机型从 Settings 返回不派发 visibilitychange）。实测：未开 `flex` → 开权限后回前台 `none` ✓
- 【优化】**「使用前请确认」弹窗中部空白 45px → 21px**
  - 拆解：正文行距余量 6 + 上组 `padding-bottom` 9 + 组 `margin-bottom` 8 + 下组 `padding-top` 9 + 标题行高上半 10。
  - 根因：两块都画成「灰底卡片」，视觉上成两个对峙块。第二块本质是链接列表 ⇒ 新增 `.dmi-group.dmi-plain`（去灰底、去上下内边距、保留左右 10px 保左边对齐）。
  - ★影响面：`dmi-group` 共 29 处、**全部在 `app-data.js`**（其他文件 0 处）⇒ 改动只作用于法律类弹窗。
- 【优化】**弹窗互斥：不叠弹窗，关掉当前回到上一个**（用户定调）
  - 实现：`app-sync.js` 一个 `MutationObserver` 观察 `body.childList` —— 有弹窗插入则把其它**可见**弹窗 `display:none` 压栈；有弹窗移除则延迟 **110ms**（留给"替换型"操作）后，若无可见弹窗就恢复栈顶。
  - **★不逐处改 30+ 个 showXxxModal**：各自 append/remove、逐处改必漏；Observer 统一拦截，**新增弹窗零改造**。
  - **★两处配套（缺一即回归）**：① `closeOpenModals()` 豁免 `data-stack-hidden`（否则「表单→日期选择器→确定」会把隐藏中的表单删掉）；② `askConfirm()` 只清其它 `#askConfirmModal`、不再 `closeOpenModals()`（否则「备份列表→删除确认」把列表删了、关掉确认框回不去）。
  - 实测 4 场景：同意→隐私政策（可见数恒 1、同意弹窗 hidden 而非删除、关闭后恢复且**勾选保留**）/ 备份列表→删除确认→取消（列表恢复）/ 记录表单→日期选择器→确定（表单恢复）/ 无残留 `data-stack-hidden` ✓
  - **E2E 新增 4 条断言固化** ⇒ 129 → **133**。
