# 视觉系统重构（2026-11-02 立项 · 待执行）

> 目的：把「一条一条打补丁」换成「一套刻度全局对齐」。目标是视觉 8.1 → 9.0，总分 8.9 → 9.4。

## 一、现状证据（实测，非估计）

统计 `www/app.css` + `app-modal.css` + `app-form.css` 的 `padding/margin/gap` 数值：

**共 19 种 px 值**：8、10、6、12、2、4、9、3、14、20、16、13、1、11、…

这就是"看着不齐"的根因——相邻元素的间距分别是 7、9、11、13，眼睛能感觉到"差一点"，但说不出哪不对。

> 字号与圆角本轮未测全（app.css 大量使用 `rem` / `var()`，正则只扫 px 返回 0）。执行前需先按 `rem` + `var(--*)` 再统计一次。

## 二、目标刻度（唯一标准）

| 类别 | 允许值 | 说明 |
|---|---|---|
| **间距** | `4 / 8 / 12 / 16 / 24 / 32` | 4 的倍数，最小 2px 只允许用于描边内缩 |
| **字号** | `11 / 12 / 14 / 16 / 20 / 28` | 6 档，替代现在的十几档 |
| **圆角** | `8 / 12 / 16 / 20 / 28` | 小控件 8、卡片 16、弹窗 20、胶囊 28 |
| **颜色** | 1 强调（靛 `#6366F1`）+ 3 功能（绿成功 / 红危险 / 橙提示） | 统计卡不再一卡一色 |

## 三、执行顺序（每步独立可回滚）

1. **提 CSS 变量**：在 `app.css` 顶部定义 `--sp-1..6`、`--fs-1..6`、`--r-1..5`、`--c-accent` 等
2. **间距替换**：按映射表把 19 种 px 归到 6 档（`7→8`、`9→8`、`11→12`、`13→12`、`14→16`、`18→16`、`20→20`…）
3. **字号收敛**：十几档 → 6 档
4. **圆角收敛**：十几档 → 5 档
5. **颜色收敛**：统计卡 7 张统一靛色系，次要三项用 `--c-accent-weak`
6. **重建基线**：`node e2e/run.js --update`

每步之后必须跑：

```bash
node test.js            # 356 项，红了立刻修
node e2e/run.js         # 133+ 项，视觉差异会红 → 确认差异可接受后 --update
```

## 四、风险

- 视觉基线 10 张全部失效 → 每步都要重建，且要**人眼确认**新图没崩
- `test.js` 有若干 DOM/样式断言，可能因数值变化报红 → 修断言时确认是真优化，不是削足适履
- `www/` 是 Capacitor 源，改完 Android 需 `npx cap sync` 重新打包

## 五、验收标准

- `grep` 结果：`app*.css` 里不再出现 6 档之外的间距/字号/圆角值
- `test.js` 356 全绿、`e2e` 全绿
- 12 张对照图（4 页 × 浅/深/弹层）间距节奏一致
