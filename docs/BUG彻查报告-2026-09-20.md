## 一、确认的问题（按严重度）

### P1 — 建议修

| # | 问题 | 实测证据 | 影响 | 建议修法 |
|---|---|---|---|---|
| 1 | **记录「距离」可以存负数**（唯一无防护的数值字段） | `edit-distance` 填 `-5` → 保存后 `record.distance = -5`（返回 `distance_minus5: -5`） | 总里程/概览统计/分享卡/年度回顾全部被算小甚至为负；用户数字键盘上有负号，很容易误触 | `saveRecord` 里给 distance 加 `Math.max(0, …)`（与 elevation/duration 同款）；并在 `normalizeRecordFields` 里补 distance/duration 净化，防导入脏数据 |
| 2 | **保存失败的用户提示是「死代码」** | 把 `localStorage.setItem` 打桩成抛异常 → 保存记录 → **toast 数 0**（用户毫无感知）；而 `saveToStorage` 里明确写着 `catch → showErrorMessage('数据保存失败，请稍后重试')` | 存储写入失败（配额满 / 隐私模式 / 磁盘异常）时用户以为已保存，**数据静默丢失** | 让 `AppStore.setItem` 把失败"冒泡"（返回 false 或抛出），上层那句提示就能生效 |
| 3 | **「抹掉足迹」保留网盘账号与密码** | 铺 `hiking_sync_config`（含 `pass: 'xk1:…'`）→ 执行抹除 → 读回 **`syncConfigStillHasPassword: true`** | 用户用"彻底抹掉"做转手/出借前的清理时，设备上仍留有坚果云地址+账号+加密密码 | 抹除时按语义一并清掉，或在抹除流程里加一句「是否同时解绑网盘？」 |

### P2 — 健壮性 / 体验

| # | 问题 | 实测证据 | 影响 | 建议修法 |
|---|---|---|---|---|
| 4 | **畸形 zip 备份导入完全静默** | `zipStoreUnpack` 返回坏 `xixi-data.json` → 走真实 `importZipBackup` → 抛 `SyntaxError`、**toast 数 0** | 用户点「导入」后没有任何反应，会以为卡住、反复点 | 调用处（`importBackup` 里的 `importZipBackup(u8)`）加 `.catch(() => showErrorMessage('备份文件已损坏，无法导入'))`；async 函数内部也包一层 try |

## 三、排查过程中我自己犯的 3 处测量错误（已更正，避免误导）

> 记下来是为了下次少走弯路 —— 这三条都不是 App 的问题，是我探针写错了。

1. **选择器错误**：`recordsTable` 本身就是 `<tbody>`，行选择器应是 `#recordsTable tr`，我写成 `#recordsTable tbody tr` → 一直读到 0 行，还让一条"搜索一致"的断言变成无意义的 `0 == 0` 通过。
2. **断言错误**：抹除后用「键是否存在」判断清没清 → 实际抹除是**写入空数组**（键还在），于是误报"没清"。
3. **绕过净化层**：脏数据测试直接给 `records` 赋值（跳过 `normalizeRecordFields`），于是看到"平均海拔 -2m"这种实际到不了的画面。

**本次踩到的两个 patch.js 坑（已写进项目铁律）**：
1. `old` 含块收尾 `}` 时，`new` **必须把它带回来**（漏了就是删掉函数收尾括号 → 语法错、被 patch.js 拦下还原）；且「逐条应用后再 `node --check`」是**假阳性**（还原后当然合法）→ 必须**内容级复核**。
2. 连续的单行断言**漏 `;`** → 下一行以 `(` 开头会被连成调用链 → **断言静默不执行**（既不 ok 也不 bad，失败数仍 0）→ 新增断言后**必须核对通过数是否正好 +N**。
