它真实的样子

下面每一张都是 App 自己渲染出来的真机界面，不是设计稿、也不是照着做的复刻。 四个标签页，加上深色模式，就是装上之后的全部样子。

01

打开就看见，
自己走了多远

统计主卡、平均三项、我的里程碑、徒步足迹、年度回顾，还有往年今日。 所有数字只做加减法：不做评分，不做排行，也不告诉你「还不够努力」。

走过的每一趟，
最后汇成一张卡。

统计主卡把次数、里程、用时、最高海拔放在一起，旁边再补三格平均值； 「我的里程碑」把成就摆在一处，达成时放一屏彩屑；徒步足迹按月点亮， 点开就是那天的记录。年度回顾把今年和去年并排放，多了少了都只是事实，不带评判。

02

记录，
不设门槛

增删改都在一处；一套字段同时管登山和徒步 —— 难度 1–5、海拔、里程、用时、小日记、心情、天气、同行人、照片最多 24 张。 按年份分组，列表与山册双视图，点开一行就是详情，详情里能直接改。

一句话也算一条记录。
照片也算。

不需要写得好看。累了就写一句小日记，收工再补细节。 没有模板，没有必填项：想只留一个日期和一个名字（山名、线路名都行），也完全没问题。

03

照片留在本机，
也留在原样

本地压缩后存进本机 IndexedDB，不上传、不识别、不做人脸归类。 详情页一排缩略图可左右滑，点开是全屏灯箱：双指放大到 3 倍、放大后拖动、双击还原。

点开一行，
这一趟就都在眼前。

照片是本地压缩后再存的，想存回相册也随时可以，全程不经过任何服务器。 山册里还会把同一个名字下的照片聚成一段「照片回忆」，隔几年翻出来看正好。

下座山，
先在这里排队

列表与日历双视图；过期、今天、明天三种徽章一眼分清。 到期的计划点「完成 / 延期」—— 完成就转成一条记录，延期就改个新日子。 计划当天早上 8:00 提醒一次，点通知直达计划页。

01
双视图List / Calendar
想按日子看就切日历，点日期看当天安排；想按轻重缓急看就切列表。同一个清单，两种看法。
02
三态徽章Badges
过期、今天、明天。状态只分三种，一眼扫完，不用点开才知道该处理哪一条。
03
完成 / 延期Done / Later
到期计划只有两种去处：完成，自动转成一条记录并放一屏彩屑；延期，顺延到新的一天。

08

安装包，
自己也要对自己负责

记录只在本机，那守门的责任就在安装包本身。 从签名校验到文本进 DOM 前一律转义，五道都留着。

/ 01
安装包签名自校验
启动时核对自身签名，防重打包：任何人改一个字节，App 都知道自己不认识这个自己。
/ 02
打包代码混淆
发布产物经过混淆处理，降低被直接阅读、改造与二次分发的可能。
/ 03
资源完整性校验
关键资源在加载前校验完整性，被替换过的界面元素不会被悄悄跑起来。
/ 04
系统备份关闭
不参与系统级备份，记录与照片不会顺着系统的备份通道流到别处。
/ 05
文本进 DOM 前一律转义
服务端返回的任何文本在进入页面前统一转义，不留注入口子。

更新日志随包内置，断网也能翻。下面是最近两版。

v1.2.3.22026-09-29
  • 应用内更新不再「一直下载失败」了 —— 之前点「立即更新」后进度卡住不动、最后报失败，是因为下载通道只有一条，一旦这条通道慢或被挡住就没有退路。现在改成多条通道自动依次尝试，任意一条成功就能顺利下完；全部通道都不行才会提示失败，而且提示里会明确告诉你可以换个网络（比如切到 Wi-Fi）再试
  • 下载安装包更快更稳了 —— 点「立即更新」「下载安装包」时，会先自动挑一条速度最快的通道，不再一头撞上容易卡住的那条；万一首选通道不通，会自动换下一条，直到下载完成
  • 「关于应用」里的 GitHub 与官方网站入口位置调整 —— 两个入口整行下移到底部「Made by XiXi」的正上方，不再夹在简介和按钮中间，找起来更顺手
  • 两个入口的图标大小统一了 —— 之前 GitHub 图标看着比官网图标大一号，现在调成一样大，一行横排更整齐
v1.2.3.12026-09-29
